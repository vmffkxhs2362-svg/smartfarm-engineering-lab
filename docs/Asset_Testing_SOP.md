## 🏛️ I. 테스트 매뉴얼(QA SOP)의 필요성 및 가치

스마트팜 디지털 자산(계산기, 노션 템플릿, KDP 도서)은 단순한 텍스트나 디자인 묶음이 아닌, **물리 수식과 제어 로직이 내장된 '소프트웨어형 제품'**입니다. 따라서 작동 무결성을 검증하는 매뉴얼은 다음과 같은 결정적 가치를 제공합니다.

1. **상품성 및 신뢰도 극대화 (Gumroad/Etsy)**: 
   "이 제품은 12가지 엄격한 물리적 한계점 테스트를 통과했습니다"라는 QA 문서를 동봉하는 것만으로도 제품의 등급이 단순 템플릿에서 '산업용 엔지니어링 패키지'로 격상되며, 환불율을 0%에 가깝게 낮춥니다.
2. **독일 엔지니어링 마인드셋 증명 (취업/아우스빌둥)**:
   독일 원예/AgTech 현장에서는 "문제를 해결하는 코드"보다 **"문제가 없음을 체계적으로 증명하는 문서화 능력(Sorgfalt und Dokumentation)"**을 수십 배 중요하게 여깁니다. 본 문서는 사령관님의 철저한 직업적 완성도를 증명하는 강력한 포트폴리오 에셋이 됩니다.
3. **시스템 업데이트 시 안정성 확보 (Regression Test)**:
   추후 기능 확장 시 기존 수식이나 제어 코드가 깨지지 않았는지 즉각 확인할 수 있는 기준선(Baseline) 역할을 합니다.

## 🧪 II. 웹 계산기 (index.html) QA 테스트 프로토콜

웹 계산기는 자바스크립트 수식 연산의 오차 및 UI 반응성을 브라우저 환경에서 검증해야 합니다.

### 1. 테스트 시나리오 1: 온실 열손실 계산기 (Greenhouse Heat Loss)
* **테스트 목적**: 면적, 피복재(U-value), 온도 차이에 따른 열손실량 연산의 수학적 타당성 검증.
* **표준 테스트 입력값 (Baseline Input)**:
  * 온실 표면적 ($A$): $1,000 \, \text{m}^2$
  * 피복재 선택: `Venlo Glass (U-value = 5.8 W/m²K)`
  * 내부 설정 온도 ($T_{in}$): $18^\circ\text{C}$
  * 외부 최저 온도 ($T_{out}$): $-2^\circ\text{C}$
  * 풍속 마찰 계수 (Wind Modifier): `1.0` (풍속 4 m/s 미만)
* **예상 결과값 (Expected Output)**:
  $$Q_{loss} = U \cdot A \cdot (T_{in} - T_{out}) \cdot \text{Modifier}$$
  $$Q_{loss} = 5.8 \cdot 1000 \cdot (18 - (-2)) \cdot 1.0 = 116,000 \, \text{W} = 116 \, \text{kW}$$
* **브라우저 테스트 수행법**:
  1. Chrome/Edge에서 index.html을 엽니다.
  2. 첫 번째 탭 "Greenhouse Heat Loss"에서 위 입력값을 기입합니다.
  3. 계산 버튼 클릭 후 화면에 출력되는 총 열손실량이 정확히 **116.0 kW** (또는 $99,760 \text{ kcal/h}$)로 렌더링되는지 확인합니다.

### 2. 테스트 시나리오 2: Heat Pump vs Gas Boiler ROI 계산기
* **테스트 목적**: COP(성능 계수) 대비 연료 절감액 및 투자 회수 기간(Payback Period) 계산 검증.
* **표준 테스트 입력값**:
  * 연간 필요 열에너지: $100,000 \, \text{kWh}$
  * 가스 보일러 효율: $90\%$ ($0.9$)
  * 가스 단가: $0.10 \, \text{€/kWh}$
  * 히트펌프 COP: $3.5$
  * 전기 단가: $0.20 \, \text{€/kWh}$
  * 히트펌프 초기 CapEx 투자비: $15,000 \, \text{€}$
* **예상 결과값**:
  * 보일러 연간 비용: $(100,000 / 0.9) \times 0.10 = 11,111.11 \, \text{€}$
  * 히트펌프 연간 비용: $(100,000 / 3.5) \times 0.20 = 5,714.28 \, \text{€}$
  * 연간 에너지 절감액 (OpEx Savings): $11,111.11 - 5,714.28 = 5,396.83 \, \text{€}$
  * 회수 기간 (Payback Period): $15,000 / 5,396.83 = 2.78 \, \text{years}$
* **브라우저 테스트 수행법**:
  * "Boiler vs HP ROI" 탭에 값을 기입하고 연간 절감액과 페이백 기간이 소수점 오차 범위 내에서 일치하는지 확인합니다.

## 🧪 III. 노션 스마트팜 OS (Notion 2.0) 수식 QA 프로토콜

노션 수식은 데이터베이스 간 관계형 롤업(Rollup)이 비어 있거나 경계치에 도달했을 때의 예외 처리(Error Handling)를 테스트해야 합니다.

### 1. 테스트 시나리오 1: 교정 기한 초과 알람 (`Calibration Status Alert`)
* **목적**: 날짜 계산 함수의 임계 구역(오늘, 과거, 미래)에 따른 올바른 이모지 경보 출력 검증.
* **테스트 데이터 세트 (Test Cases)**:

| 케이스 ID | 입력값: `Next Calibration Date` | 오늘 날짜 대비 조건 | 예상 출력 텍스트 (Expected Output) |
| :--- | :--- | :--- | :--- |
| **TC-NC-01** | 빈 칸 (Null) | 날짜 미지정 | `⚪ No Date Set` |
| **TC-NC-02** | 5일 전 날짜 (과거) | 기한 초과 | `🚨 OVERDUE BY 5 DAYS / 교정 기한 5일 초과` |
| **TC-NC-03** | 2일 뒤 날짜 (임박) | 3일 이내 임박 | `⚠️ Calibration Due in 2 Days / 2일 내 교정 필요` |
| **TC-NC-04** | 10일 뒤 날짜 (미래) | 안정권 | `🟢 Stable / 정상 (Next: YYYY-MM-DD)` |

* **수행법**: 노션 테이블에 4개의 가상 센서 행을 만들고 각 날짜를 매핑하여 위 이모지와 텍스트가 깨짐 없이 롤업되는지 육안 확인합니다.

### 2. 테스트 시나리오 2: 원액 비료 투입량 계산 (`Required Fertilizer Mass`)
* **목적**: 나누기 연산 시 분모에 `0`이 기입되었을 때 발생하는 Zero-Division 시스템 에러 차단 테스트.
* **테스트 입력값**:
  * 원액 탱크 용량, 주입 비율, 비료 순도 중 하나라도 `0`을 입력.
* **예상 결과**:
  * 에셋이 깨지거나 `NaN` 또는 에러 메세지를 뿜지 않고, 예외 처리 로직에 의해 깔끔하게 `0`으로 수렴해야 함.
  * 복사-붙여넣기한 코드 내 `if(vol == 0 or dilution == 0 or purity == 0, 0, ...)` 분기 작동 확인.
